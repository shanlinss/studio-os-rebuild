# 代发批次与供应商退款错单（075）

复用068原代发批次、不可改写的数量/SKU/店铺快照、成本版本、退款记录与操作者回执。商品实际库存、原记账支出、付款与月度平台可提现收入仍沿原服务，不复制或生成新的资金事实。

## 纠错方式

金额填写错误继续从原“修正成本”“修正实际退款金额”追加版本。数量、日期、SKU或业务店铺等原事实填错，采用作废错误登记，再关联重建正确记录。原记录与旧快照保留，作废不表示实际退货、撤回付款或撤销供应商真实退款。

代发批次详情可以作废错误批次。仍有有效退款时拒绝整批作废，必须先核对退款是否确实是错误登记；不会自动连带取消真实退款。作废后不能继续改成本、挂新退款；可从原错单“按原错单重建正确批次”。原批次编号保持占用，新批次使用新编号，保留一对一重建链接。日期、SKU、店铺、数量、供应商、来源及各行总成本都须按真实单据重核，不能按数量比例猜测实际成本。参考估算重新使用正确业务月份适用的参考依据。

退款详情可以作废错误退款，随后从原作废退款关联重建正确记录。新退款可更正原明细、数量、日期、来源及实际金额；释放的可退数量只用于原始数量上限，不改变工作室库存。实际退款金额继续由用户填写，允许明确的零元，不按原价自动计算。重建仍受同批次、有效明细、退款日期不得早于代发日、累计有效退货数量不得超过原数量约束。

## 保留真实退款的业务事实更正

真实退款不能为了改错而假装作废。新增“更正日期、数量与店铺”入口，保持原批次、原明细、退款ID不变，追加业务事实版本和同一版本的完整成本依据。原始表不覆盖，读取通过有效事实视图核对。金额、日期、数量、店铺等更正时，原真实退款的金额、日期、数量及凭证不改写；退款成本回冲随正确业务店铺/SKU重新归集。

更正须完整对应原所有行，不能用此入口增删原行。每行成本总额重新核对；参考估算按正确月份和数量重算并保留新快照，旧快照不变。有真实退款的行，数量不得改到已退数量以下，代发日期不得晚于真实退款日期，也不能直接把真实退款换挂另一SKU。没有真实退款时可核对更正SKU；有真实退款且商品身份也错误的复杂场景须继续核对关联事实，服务端拒绝静默转挂。

业务事实更正与退款/作废共用原批次锁，使用原成本版本竞争校验。后续只修正金额继续沿用最新有效日期、数量和店铺。每个成本历史版本匹配当时有效的业务事实，不能用今天数量展示旧成本。永久保存新SKU/店铺引用，防止后续删除使历史失联。

## 有效汇总与防重

075给成本/退款版本追加active/void状态，旧版本默认active，不修改原068迁移。所有数量上限、SKU成本核对和经营总览只纳入最新有效版本。成本归代发业务月份，供应商退款归真实退款月份；作废或重建后跨月合计随有效来源重算，原已录历史始终可查，不冒充月结快照。

同一供应商下的同一原始清单/结算来源忽略大小写及首尾空格防重，新批次编号不能绕过原来源检查。作废来源从原单关联重建，不能作为无关新单重新录一次。重建链接一对一，不能从同一个错单并发分支重建。原退款来源保留；重建退款可以沿用同一个真实来源编号，但同明细仍只能有一笔有效的同来源退款。

旧资料若已有同供应商来源的重复有效批次，仍允许读取，经营总览和SKU实际成本/净额保持待核对。旧关联退款的月份也会提示，不能把重复来源退款当作确定回冲；重复批次未核清前不追加退款。没有静默合并、删除或猜测原数据。原单可按核实结果作废，剩余有效来源重新参与核算。

## 事务、权限和界面

作废、修正及退款共用原代发批次事务锁。批次作废与新退款并发，只会有一个有效结果，不能出现作废批次下新挂有效退款。版本不一致要求重读。作废与重建都需要当前finance及resources授权，回执回放前重新核查；财务单独可以读取。CSRF、原请求内容校验、私人回执及后段写入失败整体回滚继续使用。

批次列表、详情、原成本及退款历史显示作废状态，作废记录只提供查看关联记录及重建入口；原版记录不覆盖。只读预览仍拒绝所有作废/重建写入及私人回执。

## 本轮范围及接续

本轮完成的是第一项中的代发批次和供应商退款错单闭环。工作室商品入库/发货/可售退货涉及实物数量流水，不能使用这套不动库存的代发作废来处理；商品数量、成本与后续领用/退货的纠错联动仍是第一项的下一步，未宣称商品整项完成。报表导入继续暂停，平台净收入与公共费用口径保持已确认规则。
