# 需求与确认状态

## 用户已明确确认

- 面向 4 人小红书电商运营团队，操作简单、直观、低成本。
- 重新开发，不沿用不满意的第一版设计和流程。
- 在当前聊天完成开发和验证，最后交付可供另一端替换的代码包。
- 使用独立 GitHub 仓库维护。
- 先制作每日工作台的可操作版本，使用示例数据确认页面和流程。
- 整体规划以用户提供的《Studio OS 网站地图与功能说明.pdf》（网站地图 V2，2026-11-02）为准，使用七大中心，详见 planning-source.md。早期四模块说明不再代表完整导航范围。
- 优先桌面网页端，不开展移动端优化；UI 与细节后续统一调整。
- 每日工作台首轮原型已获接受，继续推进功能与操作流程。

## 来自历史交接文档的明确规则，后续实现前复核

- 员工与管理员权限隔离；员工不能访问财务、薪资和凭证。
- 飞书文档承担知识中心。
- 管理员垫付允许跨月累计，集中报销，月末不清零。

历史交接文档不是页面设计稿，其标注“建议”的字段、状态和流程不自动成为确认需求。

## 已接受作为继续开发的基础，UI 后续统一调整

- 员工首页以“我的今日事项”为主区，关联素材和测试在事项详情中呈现。
- 浅色背景、白色工作面板、绿色强调色、紧凑侧栏。
- 三个简单状态：待处理、进行中、已完成。
- 支持新增、编辑、日期与类型筛选、搜索、状态切换。
- 示例成员仅用于演示；不等于登录身份或权限设计。

## 尚未确定

- 今日事项由员工自行添加、管理员分配，或两者均有。
- 团队成员是否可查看或修改他人事项。
- 每日数据填报、发布和复盘的真实业务口径。
- 旧平台、运行环境、数据库、附件存储、历史数据迁移方式。
- 管理员扩展模块本次的具体开发顺序。

## 实施顺序

需求 → 信息架构 → 页面设计 → 数据结构 → 功能开发 → 测试 → 上线。
逐页确认，未确认的原型不视为最终产品决策。
