# 需求与确认状态

## 用户已明确确认

- 面向 4 人小红书电商运营团队，操作简单、直观、低成本。
- 重新开发，不沿用不满意的第一版设计和流程。
- 在当前聊天完成开发和验证，最后交付可供另一端替换的代码包。
- 使用独立 GitHub 仓库维护。
- 先制作每日工作台的可操作版本，使用示例数据确认页面和流程。
- 整体规划以用户提供的《Studio OS 网站地图与功能说明.pdf》（网站地图 V2，2026-11-02）为准，使用七大中心，详见 planning-source.md。早期四模块说明不再代表完整导航范围。
- 优先桌面网页端，不开展移动端优化；UI 与细节后续统一调整。
- 每日工作台首轮原型已获接受，继续推进功能与操作流程。

## 来自历史交接文档的明确规则，后续实现前复核

- 员工与管理员权限隔离；员工不能访问财务、薪资和凭证。
- 飞书文档承担知识中心。
- 管理员垫付允许跨月累计，集中报销，月末不清零。

历史交接文档不是页面设计稿，其标注“建议”的字段、状态和流程不自动成为确认需求。

## 已接受作为继续开发的基础，UI 后续统一调整

- 员工首页以“我的今日事项”为主区，关联素材和测试在事项详情中呈现。
- 浅色背景、白色工作面板、绿色强调色、紧凑侧栏。
- 三个简单状态：待处理、进行中、已完成。
- 支持新增、编辑、日期与类型筛选、搜索、状态切换。
- 示例成员仅用于演示；不等于登录身份或权限设计。

- 新仓库与当前开发基线为主，用户提供的旧 ZIP 只做辅助。
- 已有数据库、连接及可直接使用的能力优先复用，不重复开发。
- 先核对独立后端及旧平台实现，区分历史归档、当前源码和实际运行配置。

## 设计与开发基线（用户再次明确，2026-11-02）

- 用户指定首轮每日工作台截图为首页视觉与交互布局基线。
- 保留问候标题、日期切换、添加事项入口、工作清单、完成进度、状态/类型/搜索筛选、右侧复盘卡片及工作提示。
- 旧 ZIP 仅复用已实现的数据库、连接、身份/权限和适合接入的底层能力；旧页面、旧导航分组和旧交互方案不主导本项目设计。
- 对接已有数据时，应调整适配层以承接新页面；如数据字段不足，记录差异再处理，不为迎合旧接口而擅自简化或改造已确认的页面。
- 完整模块范围仍按用户指定 PDF 的七大中心；截图用于锁定首页设计，不撤回已确认的整体规划。
- 示例版与云端版共用 `dist/daily-layout.mjs`，仅数据来源及当前可操作范围不同。云端仍为只读，新增/完成/复盘安排暂不可操作，不能假装写入已接通。

### 2026-11-02 用户补充：内容与知识沉淀

- 草稿只保留本机保存，不开发多人同步。
- 知识库只做分类、查找与飞书文档导航；正文在飞书维护。
- 仅管理员维护导航的分类、名称、说明、标签与链接，操作放在当前页面，不单独设编辑板块。
- 复用现有知识条目与管理员权限；已有正文保留原数据，不新增正文编辑器或协作草稿存储。

用户确认知识库只导航到飞书，不做单独编辑器和正文存储。工作台只维护必要的标题、分类、说明、标签与飞书链接，管理员在同页管理，员工按权限阅读。SOP 的步骤、截图及正文均在飞书维护，不建立正文副本、正文同步或草稿多人协作；不删除旧包已有的历史资料。
