# 资源敏感字段与设备采购资料（2026-11-03）

本轮完成设备采购资料的结构化保存和金额访问边界，沿用原设备与财务支出标识、现有授权、会话、CSRF和金额工具。其他资源模块新增敏感字段时仍须逐项接入，不能因为已有权限名就宣称全部资源、全站店铺隔离或成本核算已完成。

## 复用核查

先核查旧独立后端/migrations和当前equipment、finance、permissions实现。旧033明确不含采购/成本模型，未发现可直接使用的设备采购结构化字段；当前037提供设备档案、借还、事件及回执，原账本已有真实支出/版本/凭证。

因此不新建资产、成员、店铺、账本或授权系统。052只补引用原equipment_assets的equipment_purchase_versions及私人equipment_purchase_receipts。原001–033不改。采购快照与普通设备行分开保存，原设备服务中SELECT *生成的借还快照不会包含金额。未把旧备注解析成采购金额，也未给旧设备填0。

## 权限矩阵

| 信息或操作 | 当前要求 | 状态 |
| --- | --- | --- |
| 共用设备名称/编号/型号/位置/可借状态 | 有效登录，沿用原共享目录及本人借还限制 | 保持原实现 |
| 设备内部说明、团队借用、普通档案维护 | resources | 保持原实现 |
| 采购日期、金额、供应商、支出引用、采购历史 | finance | 本轮实现，员工与仅resources管理员不能读取 |
| 新增或修改设备采购资料 | finance和resources同时具备 | 本轮实现，事务内复核当前授权 |
| 原支出及私有凭证/导出 | finance，继续原接口范围 | 不额外授予，也不复制凭证 |
| 人员、工资及账号安全 | personnel/payroll/account_security分别要求 | 采购授权不替代这些能力 |
| 手机卡实名信息、后续采购与商品成本 | 对应模块建模时再接管理员授权、服务与投影 | 尚未建模，不先开放通用敏感备注/凭证存储 |

超级管理员沿用全部已实现权限。没有新增空壳权限项，也不把资源管理员自动升级为财务管理员。只具有finance的管理员可从设备目录采购入口查看资料，不能修改；同时具备resources才能保存。当前只读预览不显示保存入口。

## 数据与来源

每次保存追加采购版本：原设备标识、递增版本、可空购买日期、可空整数分金额、供应商、可空原支出标识及其当时快照、设备基础快照、原因、操作者当时用户名与时间。金额使用原money.ts十进制工具，最高2147483647分；先拆分十进制字符串，再以整数分保存，避免小数乘法误差。留空表示未知，0表示明确免费/零价，两者保留区别。

采购资料有独立版本。普通设备编辑、维修、借还继续使用原设备版本，不会覆盖采购资料；采购变更也不改原借还状态或单位。更新前锁原设备行，核对最新采购版本；同一编辑版本竞争只接受一次。历史及回执在数据库中不可改写/删除。

支出引用必须带当前原支出版本，事务内锁定并核对。保存只建立来源引用，不登记支付、不复制支出、不计算摊销或成本。不要求采购金额等于支出总额；一笔支出可能涉及多件设备，引用不代表已经分摊，也不自动汇总为额外费用。

采购版本保留当时原支出日期/说明/金额/版本。之后原支出修改，采购页提示来源已变化，历史仍保留旧快照；再次保存必须选取当前支出版本重新核对。不能把来源变化当成自动修改设备采购价的理由。

## 接口与界面

- GET `/api/equipment/catalog/:id/purchase`：finance；设备基础身份、最新采购版本及当前关联支出/来源变化提示。
- POST 同路径：finance+resources；请求标识、采购版本、购买日期/金额/供应商、原支出与版本、必填原因。
- GET 同路径`/history?offset=…`：finance，50条分页，完整保留历史。
- GET 同路径`/receipts/:key`：仍具finance的原操作者，且匹配原设备；不向其他人或只读代理开放。

设备目录按财务授权增加“采购资料”入口，继续使用原弹窗和页面风格。财务查看者只读，两项授权具备时可编辑；原设备备注提示将金额放入采购资料。表单保留未保存内容、版本冲突和不确定保存的回执核对机制。

普通设备列表/详情、本人借用、原设备操作历史及其数据库快照、原设备操作回执均不增加采购字段。独立采购历史不会并入普通时间线；不能靠隐藏按钮代替服务端隔离。旧自由文本可能包含人工录入的敏感内容，本轮不假称能识别并自动清理；新的结构化采购字段与说明必须放在受保护入口。

实际页面操作核对仍按用户要求暂停。只进行契约、HTTP和临时数据库验证，不写云端或上线。

验证结果：137项前端/接口契约、197项真实后端，共334项检查通过；新增11项真实后端、3项契约与1项只读代理。原33升级52及重复迁移通过。
