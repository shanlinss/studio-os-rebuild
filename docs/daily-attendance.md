# 员工日常考勤首版（2026-11-03）

使用数据库服务器时间，以 Asia/Shanghai 判定日期；不接受客户端上班、下班或工作日期。当天重复登录、换设备、退出后重登都保留同一原工作段和首次时间；已经结束的当天也不重新起算。浏览器刷新、状态查询、持续打开、关闭、断网和休眠均不写入打卡。

## 今日工作与结束工作

员工首页增加今日考勤卡，显示原上班/下班时间、截至本次读取的时长、工作状态及待核对原因。原工作清单和首页设计保留。员工“我的考勤”和“个人资料”归到我的工作台，不需要进入人员中心或系统设置；管理员团队考勤入口仍保留。

“结束工作并退出”先明确提示会登记实际下班，并退出该账号所有设备；确认后检查当前会话、员工角色、有效成员、原工作段归属和版本，写原签退、版本、审计、持久回执，并清理原 sessions。所有步骤同事务提交，任一失败全部回退。多设备或重复点击不会写两次下班。

普通“退出登录”只撤销当前会话，不登记下班，不影响其他设备。结束工作成功后再登录仍显示原已下班记录，不自动重新开始。同日继续使用业务页面不会改变考勤，后续补正需走申请/审核。

结果不确定时先核对状态，不自动重复提交。如果服务端已经结束并清理会话，需要重新登录核对当天记录；重登不会覆盖原时间。员工重新登录后可以读取本人原持久回执，不能读取他人的回执。状态读取按同一员工锁等待相关保存完成，仍是只读，不因 GET 自动上班。

## 时长与历史异常

时长按有效签退减有效签到；没有签退时仅显示截至本次读取的时长，不判定最终“时长不足”。午休计入 8 小时，不额外扣午休。晚于 10:30 与是否满 8 小时分别判定，满 8 小时仍保留迟到提示；毫秒精度保留，不把刚好不足 8 小时四舍五入成已满。

这些提示不计算工资、奖罚或应出勤天数。工作日历、节假日/调休、请假、月度统计、考勤锁定和工资核算仍待后续实现，不能把每日时间差等同正式工资依据。

已有当天唯一且时间有效的原工作段直接建立关联，原时间、版本、历史事件保持；当天已有签退也不重新起算。对历史多段、前一天未签退、跨日或未来异常时间采用保守处理：提示待核对，不合并工作段、不猜下班、不自动延长前日时长，也不直接把跨日记录作为正常当天上下班。前日遗留未结束时，本轮不自动开始新日；需补正后重新登录，或在后续补卡流程中核实真实时间。

管理员仍可查看/审核历史；管理员本人的手动上班、签退和补卡申请入口拒绝，以免与“不参与考勤”的新规则冲突。旧原始记录不删除。补卡申请与管理员审核的底层仍在，下一步接新工作台的异常处理入口，不能计为本轮已完成界面。
