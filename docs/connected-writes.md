# 保存流程 · 隔离联调版本

## 当前状态

已实现素材新建/编辑、管理员产品新建/编辑、原事项登记发布、原发布追加观察数据。表单遵循新页面设计，调用旧 HTTP 契约；没有平行数据库、前端假保存或云端样例记录。

`npm run dev:cloud` 仍为只读：客户端默认禁止 mutation，本机代理拒绝所有非 GET 并去除会话中的 mutation token。未启用真实云端保存。

`node tests/write-fixture.mjs` 启动 `http://127.0.0.1:4177/`，使用假身份、内存资料和已知测试 token，不读取或转发 Cookie，不连接云服务或数据库。退出后记录消失。该 fixture 仅验证新 UI 和适配器相接，不验证原后端实现。

## 已对照的原接口

| 对象 | 接口 | 保存规则 |
| --- | --- | --- |
| 素材 | POST `/api/materials`、PATCH `/api/materials/:id` | 原 `metadata` 与 `storeIds` 保留；编辑携带 `expectedVersion`；无删除/归档映射 |
| 产品 | POST `/api/products`、PATCH `/api/products/:id` | 新建填写阶段；编辑仅资料，不改阶段标识；保留店铺关联、说明、版本 |
| 发布 | POST `/api/tasks/:id/publications` | 原事项、实际北京时间、HTTPS 笔记链接；使用原详情中的关联素材，测品非模板任务须选择素材 |
| 观察 | POST `/api/tasks/:id/publications/:pubId/snapshots` | 原发布标识、采集时间、多次追加；未知为 null，真实零为 0，成交状态与数量一致 |

契约来自上传包 `studio/server/materials.ts`、`products.ts`、`workflow.ts`；线上读取另行核对。尚未证明旧包全部写接口与当前部署完全一致，故未在云端启用。

## 保存与出错行为

- `cloud-connected` 是显式构建开关，目前只由隔离 fixture 提供。普通静态原型和真实只读代理均不设置它。
- 会话 token 只保留在适配器闭包，不交给 DOM 或 localStorage。会话失效后清除；后端仍负责身份、CSRF、归属和权限检查。
- 同一保存路径的并发点击被阻止。409 保留编辑内容，要求核对最新记录；不会覆盖他人版本。
- 网络中断、超时、5xx 或成功响应解析失败均视为结果未确认，不自动重试。对应资料经成功校验的读取后才解除适配器阻止；原表单仍不直接重试，需核对后重新打开。
- 取消有修改的表单时可继续编辑或放弃。保存期间关闭被阻止。成功保存后重新读取列表/详情，不在前端伪造新版本。
- 浏览器时间字段标注北京时间，转换显式 `+08:00`，不依赖操作者电脑时区。
