# 补卡申请与管理员审核（2026-11-03）

员工从“我的考勤”查看本人原始与核准时间，进入已有记录申请补正上班或下班。缺少整条工作记录时可选择“无原记录，申请补上班”，由管理员审核后建立原考勤工作段，再从该记录申请补下班，不推算缺失时间。

页面分为考勤记录与补卡申请两个视图，按日期查看；申请可筛选待审核、已批准、已驳回和全部。管理员进入补卡审核时默认查看团队待审核。员工仅查看本人记录与申请，不接受通过参数切换成团队或他人范围。每页 50 条，列表和总数、历史和总数分别在同一只读快照读取。

## 申请、核对和审核

员工填写已发生的真实北京时间及原因。工作室记录的补正须属于原工作日，且上下班顺序成立；跨日复杂情况保持人工核实，不借普通补卡暗改日期。表单保留秒和毫秒，修改原因不会把原申请时间截成整分钟。提交后不直接修改有效打卡。

待审核申请可由本人核对修改；已批准/驳回的申请保持历史，不能覆盖。驳回后员工可以从原考勤记录重新申请。相同原工作段、相同方向已有待审核申请时，新的保存标识也不能重复创建；无原工作段则按本人、方向和申请的北京时间日期识别。

管理员详情同时展示申请时间/原因、原始上班/下班、当前核准时间、状态及历史。批准将申请时间写入原 adjusted_in/adjusted_out；不改写 original_in/original_out。驳回不改时间，必须提供说明；新页面对批准也要求填写核实说明，方便追溯。

原考勤变化时，旧申请不能直接批准。员工在待审核申请中重新核对修改后，刷新对原记录的版本引用；不另复制一份申请。申请和原工作段的版本分别校验，多管理员竞争只会处理一次。

审核前明确显示阻塞原因：原记录已变化、原本缺失的当天现在已有记录、还有其他未结束工作段。阻塞时不提供批准入口，但允许驳回说明；服务端仍重复检查，不能通过直接调用绕过。没有原记录的补上班若受到其他未结束工作段阻塞，需先核对处理这些原记录。

## 历史、回退和底层复用

完全复用原 attendance_periods、attendance_corrections、attendance_events 和 attendance_receipts，本轮没有新增表或迁移。新增的详情读取按本人/管理员权限取原记录；状态筛选、来源版本刷新及重复申请拦截补在原服务上。

修改及审批前后值、操作人、服务器时间、申请原因和审核说明进入原历史。详情可跨页查看；补正应用明确展示核准时间前后变化。申请新增/修改、批准/驳回都沿用原持久回执；保存中断先核对本人回执，不能自动重复应用时间。

审核在原员工事务锁下执行：来源调整、申请状态、事件、审核人/审核时间及回执一起成功或回滚。后段审计失败不留下部分核准时间。员工不能批准，管理员不能通过员工补卡入口给自己打卡；管理员仍可处理团队历史。新财务/账号授权不等于人员细分授权，人员细分仍按后续清单推进。

只读代理只新增申请筛选、记录详情和历史 GET 及必要前端模块，继续阻断申请/修改/批准/驳回等写入和私有回执。新详情尚未部署时显示读取失败，不生成演示申请或通过旧页面代写云端。
