# 请假申请与审核（2026-11-03）

员工在“我的考勤”中的“我的请假”提交类型、开始/结束时间及原因；管理员在同一页面的“请假审核”查看团队申请。类型可以按实际填写，事假/病假/年假/其他只是输入建议，不代表系统设定的假期额度或法定待遇。

起止时间统一按北京时间填写，保存为带时区的真实时间点，支持未来、过去、跨日和跨月的申请，保留秒与毫秒。结束必须晚于开始。不自动把一个跨夜时间段折算成若干出勤日、扣除午休、扣减工资或变更上下班记录。

## 状态与操作

员工的待审核申请可以修改或说明原因后撤回；审核完成后不能再覆盖申请。管理员批准或驳回均须填写说明。已批准请假若安排取消，由管理员通过“撤销批准”记录原因；保留原批准人、原批准时间和原审核说明，同时记录撤销人/时间/原因。撤回、驳回、撤销均保留记录，不删除历史。

同一员工的待审核或已批准时间段不得重叠，类型不同也不允许重叠；前一段结束恰好等于后一段开始可以相接。不同员工可以使用相同时间段。撤回、驳回或撤销后，相应区间不再占用，可以重新申请。这里是申请排重，不是自动判断出勤或工资。

列表支持本人/团队、状态、日期和每页 50 条；日期按时间段与所选北京时间日期相交筛选，跨月申请不会因起始日在上个月而被漏掉。详情展示当前状态、时间、原因、审核/撤回/撤销说明，以及可跨页核对的完整修改和审核历史。

## 数据与保护

旧后端没有请假对象，043 只新增 leave_requests、leave_events 和 leave_receipts，继续引用原 accounts 与 members。没有另建人员或登录档案，也不把请假写成 attendance_periods 的签到/签退，更不会新增工资或财务费用。

员工只能读写本人申请，需关联有效成员；管理员可以核对团队资料，但不从员工入口给自己申请。列表、详情、历史和处理动作均在服务端约束；本轮没有新增附件。人员管理进一步分权仍待后续实现，不把现有管理员范围算成完整人员授权体系。

写入时重新检查当前账号角色和启用状态；员工修改/撤回再次核对原成员关联。按员工加事务锁检查重叠，申请、状态、版本、审计及持久回执同一事务提交，失败全部回滚。重叠提交只有一笔成功；同标识重复请求只记一次，多管理员并发处理只有一个版本成功。

审核、撤回和撤销均保留操作人姓名快照及前后值；事件表在数据库中禁止更新或删除。表约束保证时间顺序和各状态相应审核/撤回/撤销字段完整。重叠校验在服务端事务中实施，不宣称已对绕过服务端的任意直接 SQL 建立区间排斥约束。

保存响应中断先查询本人持久回执，不自动再次提交。员工和其他管理员不能读取该操作者的私有回执。只读代理只转发列表、详情、历史 GET 及前端模块；提交/修改/审核/撤回/撤销和私有回执都不转发。
