# 记账本用途、归属与按人待报销（070）

用户于 2026-11-04 明确公共费用不分摊给店铺。记账本应优先满足日常支出、个人垫付和待报销，再逐步接入工作室及店铺经营汇总。

## 本次复用

继续使用原 expense_records、expense_categories、members、stores、expense_receipts、结算明细和报销记录。不复制支出或凭证，不新增费用分摊表。原代码包的 store_id 只能表达关联店铺，空值不足以确认公共费用；因此 070 仅补用途与归属字段，以及操作者专属的归属核对回执。

旧支出统一保留 unclassified 初始状态，原 store_id、金额、垫付人、结算、凭证和请求哈希不改写。已有店铺关联仍可见，但需明确用途与归属后才进入已确认运营费用。不会按店铺数量、启停日期或比例重算公共费用。

## 归属与用途

- 费用归属：工作室公共、店铺专属、待核对。公共归属必须不指定店铺，店铺专属必须明确原店铺 ID。
- 支出用途：日常运营费用、库存采购、预付款项、待核对。
- 只有用途与归属均明确的日常运营费用进入对应费用汇总；公共运营费用与店铺专属运营费用分列。
- 库存采购、预付款单列，不混入这里的运营费用。归属或用途待核对时整笔进入待核对金额，不同时在其他汇总桶计数。
- 公共费用只在工作室最终汇总扣一次。店铺收入减专属成本得店铺利润，店铺利润合计再减公共费用。当前组件只展示运营费用，并未合并商品成本、包材消耗、工资、收入或完整利润。

## 记录与核对

新增/编辑支出可同时填写用途和归属，与原金额保存及 expense_events 审计同一事务。旧调用方不传新字段时，新记录保持待核对，编辑保持原分类；原创建请求哈希结构在没有新字段时维持兼容。

已纳入结算的支出继续禁止修改金额、垫付人及其他原业务事实，但允许单独“核对用途与归属”。独立核对仅修改 expense_scope、expense_use、store_id 和版本时间，不触碰结算明细或报销流水。财务授权即可操作，已有停用店铺可保持原关联；新增归属不能选停用店铺。版本竞争返回冲突；请求重复返回原结果，换目标或内容不能复用。写入失败连同原审计和回执整体回退。

归属核对也会递增原支出版本，已引用该支出的采购/手续费来源可能提示重新核对，保留原金额快照。独立回执不依赖支出删除级联，原支出删除规则与审计继续沿用已有实现。

## 记账本页面

保持既有桌面视觉体系，优先展示“记录支出”、累计待报销、按人待报销、按月费用归属概览和支出明细。销售、已售成本和代发成本入口收进“经营与成本明细”。原结算与报销入口继续使用，不新增报销流程。

按人待报销 = 尚未纳入结算的垫付 + 结算后尚未支付金额。已关联结算的费用不再计入未结算垫付，实际报销减少欠垫付人的余额，不重复扣费用。余额跨月保留，不随明细筛选变化。

费用概览按选定月份的全部支出汇总，店铺启停不删除历史。明细可另按付款方式、归属与关键词筛选；明细筛选金额单独标注，不冒充全月经营费用。公共费用、专属费用、库存采购、预付、待核对分开，尚不计算完整工作室利润。

本次仅本机验证，实际页面操作核对仍按用户要求暂停，未写云端。下一步继续经营总览的收入与各项成本来源整合，遵循公共费用不分摊和费用/报销不重复计入的规则。
