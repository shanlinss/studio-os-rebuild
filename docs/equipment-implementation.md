# 设备首版实现（2026-11-03）

## 用户操作

工作室财产管理提供设备入口，与原拍摄样品并列；员工在拍摄页及需求详情可打开设备借还。继续使用已确认的桌面界面体系，不做移动端适配。

管理员登记设备编号、名称、型号、保管人、归还位置和内部说明；可编辑原档案、送修、完成维修、停用和恢复。内部说明仅管理员读取，目录共享必要的编号、名称、型号、保管人、位置、状态。编号按不区分大小写唯一校验。

已关联有效成员的员工可以借一台可用设备，填写使用位置及可选原拍摄需求。仅本人可归还或更新借用位置，管理员可看团队借用但不能代别人归还。归还选择完好或异常，异常必须说明并进入待维修，管理员完成维修后才能再次借出。借出中的设备不得直接维修或停用；停用保留档案和历史，可由管理员说明原因恢复。

设备目录、本人/团队借用、管理员操作历史均每页 50 条。我的借用包含本人全部需求，不把当前需求或单页当成全量。借用详情按 ID 独立读取并校验范围，较早分页记录同样可办理归还。

## 原底层复用与新增

复用 accounts、members、shooting_requests、原认证与 CSRF、登录绑定和管理员范围。借用人从当前账号推导，不接收请求指定 owner。新增 037 的设备目录/借用/事件/回执是缺失的设备事实，不生成第二套样品、产品或身份。

每次保存带 requestKey；事务内检查当前操作者、重放回执、原版本及设备行锁。数据库部分唯一索引再保证每台设备最多一条未归还借用。重复同一请求返回原结果，改变内容复用标识冲突，失败操作整体回滚。客户端保存结果不明先核对本人持久回执，不自动重试借出。

归还时记录真实服务器时间、状况、说明及归还位置；随后改设备存放位置不会改写已经归还的历史。档案编辑保留借用、维修和停用状态；全程没有物理删除接口。维修、停用、恢复保留操作者和原因。

## 验证与未完成

累计 104 项自动检查通过：69 项前端/接口契约及 35 项原后端/临时 PostgreSQL。新增流程、权限、并发、幂等、分页及迁移已覆盖，原 33 个迁移未变，追加至 37。

实际页面操作核对继续按用户要求暂停；未在真实云端登记设备、借还或运行迁移。现有云端后端尚未部署设备接口时，只读页面明确提示不可用，不回退为示例数据。设备图片、采购成本/折旧、正式报废核销不在本轮；产品/包材仓库仍待下一项实现，不用设备或样品数量替代。
