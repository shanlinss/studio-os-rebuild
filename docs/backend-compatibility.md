# 原后端复用与本机完整联调

## 实现范围

从用户上传包选择复用独立的 `studio/server`（48 个 TypeScript 文件）和 `studio/migrations` 的原 33 个迁移文件。没有复制旧 Web 界面、平台飞书依赖、环境文件或云端数据。原文件 SHA-256 记录在 `backend-source-manifest.json`，便于区分复用来源与本项目的兼容修改。

本机验证数据库版本为 PostgreSQL 18.6，尚未核对云端实际版本。

兼容修改包括 `personal-todos.ts`、`workflow.ts`、`lab.ts`、`app.ts`、`shooting.ts`、`knowledge.ts`、`finance.ts` 与 `readiness.ts`；新增 `account-access.ts`、`equipment.ts` 与 `warehouse.ts`。仅追加 034–038，原 001–033 不变。正式部署仍应以实际服务的迁移历史和文件校验为准，不能仅据旧包推定现场版本完全一致。

## 新界面需要的兼容

| 能力 | 复用与扩展 |
| --- | --- |
| 本人事项 | 保留原 owner 校验、请求重放标识、版本冲突与审计事件；计划日期、截止时间、实际完成时间追加到原 `personal_todos` |
| 原事项分类 | 保留旧分类，同时接受已确认首页中的分类；不批量改写旧值 |
| 旧请求 | 省略日期字段的创建请求保持旧 hash；旧编辑请求保留已有日期；显式 null 才清空 |
| 完成时间 | 新建为完成或从其他状态转为完成时记服务器时间；再次编辑不改完成时间；重开清空。历史缺少真实时间保持未知 |
| 先建实验 | POST `/api/lab/experiments` 沿用原实验、轮次、素材关联，允许尚未派发；旧 POST `/api/admin/plans` 仍要求执行安排 |
| 稍后派发 | POST `/api/lab/experiments/:id/rounds/:round/assignments` 写回原 `tasks`；核对当前账号负责人，原实验版本锁与事务保证一致 |
| 派发重放 | `lab_dispatch_requests` 仅存幂等回执，不是第二份任务表；同请求返回原任务，不重复派发。同账号已有本轮事项则提示查看原记录 |
| 发布到结论 | 继续使用原 publications / snapshots / lab_reviews 和结论字段；实验结束后保留资料，不继续新增发布或观察 |
| 首页与记录 | 未排期持续事项保留文字标记；已结束实验不占用当前待处理清单，不因此伪造事项完成。执行记录按真实发布/完成时点展示 |

GET `/api/workbench/capabilities` 返回兼容版本。新客户端只有确认对应能力后才发送新的事项/实验请求；旧云端不支持时不能把日期丢掉后保存。保存由原后端继续验证会话、CSRF、权限、所有权与版本。

## 运行和隔离

1. `npm ci` 安装锁定依赖；纯静态示例和只读预览仍无需安装服务端依赖。
2. `npm test` 验证前端数据契约和只读边界。
3. `npm run test:backend` 编译复用后端，运行真实 HTTP + PostgreSQL 测试。
4. `npm run dev:integrated` 启动 `http://127.0.0.1:4178/` 的完整本机联调页。

测试用 PostgreSQL 通过 [embedded-postgres](https://github.com/leinelissen/embedded-postgres) 在本机临时目录运行；它是开发依赖，生产仍使用已有 PostgreSQL。仅监听 `127.0.0.1:55432`，端口已占用就退出，不连接既有实例。随机数据库凭证不打印、不写进仓库；不读 `.env`、不使用云端密码、不改变系统用户，退出后清理临时数据。

集成预览使用公开、可丢弃的 `local_admin` / `local_employee_a` / `local_employee_b` 测试账号。密码是开发启动文件中的 `localTestPassword`，只能用于脚本当次创建的本机库；不会被部署或写入云端。预览采用原登录、HttpOnly 会话与退出接口，没有绕过正式权限。新导航按已确认网站地图和两类登录角色组织：员工可到考勤查看本人资料，但不出现财务、角色、团队账号和竞品管理等入口；页面权限仍由原服务端校验。测试资料均明确标注“隔离”。

## 验证证据与边界

后端测试从原 33 个迁移创建旧库，放入历史待办与旧请求 hash，再升级至 38 个迁移。覆盖旧请求重放、空历史日期、本人权限、CSRF、并发创建、冲突编辑、旧客户端保留日期、真实完成时间、非法日期回滚，以及实验草稿、派发回执、员工范围、原发布与多次观察、复盘和结束后的拒写。

浏览器实际操作已验证：登录 → 新增事项 → 编辑保留排期 → 标记完成 → 执行记录；创建未派发实验 → 引用素材 → 按账号安排 → 本人首页进入原事项 → 发布 → 回填 → 复盘 → 结论页直接引用。测试结论只说明系统链路，不形成业务效果判断。

这不是线上数据库迁移或生产部署验收。真实云端继续通过 GET-only 预览访问，未执行迁移、SQL 或业务写入。后续仍需文件、拍摄交付、其他业务写入、现场迁移核对与替换回滚方案。

036 在原 accounts 增加乐观版本，并建立 account_access_events 记录已有账号角色/启停的前后值；沿用原 sessions 及成员唯一绑定。就绪检查同时验证新增字段和审计表，缺失时拒绝就绪。未修改旧迁移或在云端执行新迁移。
