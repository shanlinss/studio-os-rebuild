# 工资确认、锁定与 Excel 导出

入口仍在考勤页的“基础工资与工资草稿”，沿用桌面设计及独立payroll授权。没有增加移动端、员工工资单或支付功能。

## 工资确认

确认前在同一可重复读事务检查当前草稿ID、此前工资确认版本、有效考勤锁定及来源一致、当月生效基础工资。草稿或来源已变化时拒绝确认，不能通过直接接口绕过核对。需要必填确认说明和明确确认操作。

确认后冻结员工/月份、金额、草稿、基础工资、考勤锁定及汇总依据，保留确认人和时间。修改金额必须先说明原因重新开放，再修订草稿并再次确认；原快照不可改写。历史按50条分页，列表只读元信息，点击单独读取快照。

草稿修改和工资确认共用原成员/月串行锁及数据库版本协调行，避免事务等待期间凭旧快照确认已被替换的草稿。重复请求只保存一次；版本变化不覆盖另一管理员操作，回执失败完整回滚。

基础工资或原考勤后续仍允许纠正。原锁定工资不随来源修改，页面提示“来源已有变化”；当前来源不一致时不能作为新导出的依据。需重新开放、核对草稿并重新确认。并发发生在事务读取快照之后的来源变化，会在再次读取时显示，不声称冻结全部数据库。

工资确认、重新开放和导出均不登记实际支付，也不生成记账本流水。本次没有确定扣薪、绩效、社保或个税公式。

## 工资表导出

“选择本月工资并导出”先列出员工状态，授权人员明确选择本次人员范围。未有效确认或来源变化的员工不可选入，界面说明其原因，不使用0金额填补。

保存导出时再次逐人核对确认版本、最新草稿、考勤与基础工资。所选任何一人无效就整次拒绝，不生成半份导出记录或悄悄跳过。允许一次1–100个明确确认版本，重复ID或跨月版本拒绝。

输出真实.xlsx文件，包含“工资汇总”和“确认依据”两张表：人工确认的四项金额、合计、确认版本/时间/人、原草稿说明、基础工资及考勤引用、导出范围与记录。金额为数字单元格，整数分转换成精确两位小数；总额仅相加，不重算业务公式。姓名和说明使用文本单元格，类似公式的姓名不会变成执行公式。

文件结构参考[微软SpreadsheetML文档](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)，由后端输出自包含OOXML包，不依赖本机Excel或外部导出服务。绿色表头、金额两位小数、冻结首行及说明换行与工作台方向保持一致。

每次导出在同一事务保存原操作者、请求键、选定快照、时间和文件SHA-256。网络结果不确定时，可核对私人回执下载同一份文件，不重复生成导出记录；页面下载前检查文件类型、包标识、大小和哈希。

“我的导出记录”仅显示当前操作者自己的历史导出，支持分页和重下载当时文件。历史文件明确标注可能已有后续更正，不将它伪装为当前有效结果；当前工资应重新核对再导出。其他薪资管理员也不能通过猜ID读取他人的私人导出文件或回执。撤销薪资授权后连本人旧文件也不能再读取。

## 数据与验证

048追加不可改写的payroll_confirmations、payroll_confirmation_receipts、payroll_exports；payroll_month_heads仅为草稿/确认并发协调行，不存业务金额。复用原账号、成员、基础工资、草稿和考勤，不复制身份、连接或平行工资台账。原001–033迁移保持不变，旧33版新增15项迁移至48，重复执行无新增。

新增12项真实后端、4项前端契约及1项只读代理检查。完整累计272项（120前端/152后端）通过。导出实际字节经独立ZIP/CRC/XML解析，验证两张表、数字及文本类型、精确金额/合计、无公式节点、回放相同文件和权限边界。未把这些检查宣称为Excel应用实际打开或浏览器操作验收。

云端只读预览仅允许工资确认历史/详情及候选状态读取，阻止确认、导出创建、私人导出列表/文件及回执。云端未应用迁移、写入或部署；实际页面操作核对按用户要求继续暂停。

后续仍需补齐管理员不打卡时的工资路径、人员离职适用范围等缺口，再按总清单推进工作室资源、分归属库存及收入/月结。实际发薪登记及其财务关联需与工资确认分开设计。
