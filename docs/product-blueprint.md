# 页面与操作规划 · 连续开发基线

2026-11-02。先依据已确认七中心规划设计，再核查现有底层；不逐页等待阶段验收。桌面端优先，原首页布局保持。

## 主流程与对象

产品档案 → 素材收集/拍摄 → 实验与内容安排 → 执行/发布 → 按观察时点回填 → 复盘与知识沉淀。

产品、素材、实验、执行事项、发布记录各保留稳定标识。页面是同一对象在不同阶段的视图，不另外复制任务或创建平行库。

## 产品管理

目的：快速找到正在运营的产品，进入其资料与相关工作。

- 顶部为产品总览、在用/停用切换、搜索与新增入口。
- 主区使用产品卡片，突出名称、所属店铺、状态和测试进度。卡片进入右侧详情。
- 详情聚合基础资料、内容要求、素材/拍摄/测试入口和业务记录；信息只维护一次。
- 新建/编辑使用简短表单，停止使用保留历史关联，不以删除代替停用。
- 不因旧系统把产品放在测品模块，就让新产品档案与测品执行混成一个页面。

## 素材拍摄

目的：看清要拍什么、谁负责、何时交付，以及交付是否符合要求。

- 状态筛选、搜索和负责人筛选位于主列表上方。
- 列表突出产品/需求、负责人、交付时间、拍摄项完成情况和当前状态。
- 详情按“要求 → 有序拍摄清单 → 交付与反馈”组织，参考资料就近展示。
- 拍摄项可以勾选完成，保留补拍原因与交付历史；只读联调阶段仅查看。
- 领取归还从详情关联样品同一档案，不能另建拍摄库存副本。
- 具体状态和权限先保证旧接口的事实读取不失真，最终操作由本规划与当前授权控制，不整搬旧界面。

## 内容编排

目的：以一周为单位安排内容工作，发现空档与未排期事项。

- 顶部前一周/本周/后一周，配合账号或负责人筛选。
- 中间七日周视图，内容卡片直接显示事项、账号、负责人和阶段；点击打开原事项。
- 未排期事项独立成区，不能默认塞进今天。
- 调整安排沿用原事项/计划的标识，不能通过“新建日程”复制任务。
- 本轮先展示已确定的计划日期。拖动改期在接口及并发版本适配后开放，不能做仅改变外观的假保存。

## 发布管理与数据回填

目的：让执行人快速找到待发布、待首轮回填和已回填内容。

- 与内容编排保留不同入口，但共用执行事项与发布记录。
- 按事项/发布进度组织列表，详情显示发布链接、北京时间、内容版本和多次观察记录。
- 数据回填保留采集时间与观察窗口；未知为空，0 是真实的零。
- 实验是否有效由复盘结论决定，不因某指标增加或事项完成自动标为成功。
- 发布附件、实际封面及参考素材保留所属记录关系；不自动公开私有文件。

## 后续页面的设计方向

- 测品中心：产品测试执行队列，聚合阶段、账号安排、测试反馈和下一步，引用产品档案。
- 模板库/标题库：可检索的复用资源，卡片/列表到详情，再引用到创作和测试。
- 工具箱：按用途分组的工具入口与简短说明。
- 知识库/学习与复盘：目录、分类和搜索，正文就近阅读或打开原文；测试结论仍引用业务结果。
- 人员/账号：职责、成员关联、运营账号状态；业务账号与登录身份分开。
- 财务/库存/资产：保持管理员边界，按现有可复用事实与已确认规则设计，不自动扩展为工资、绩效或完整会计系统。
- 系统设置：基础资料与权限分开，个人资料放本人信息；账户含义不明时不重复造一份资料表。

## 交付与验证

1. 每次开发先更新本规划的具体页面与流程，再记录底层复用来源。
2. 新界面采用已确认的浅色/绿色工作台视觉体系，详情抽屉保留上下文。
3. 可用底层直接适配；需要扩展时只补差异，不改旧迁移、不另起相同数据库能力。
4. 真实云端目前仅作读取联调。写入代码在模拟接口/隔离环境验证，不能用真实业务记录做破坏性测试。
5. 将实现、已验证、受环境限制的部分分开记录；不把规划页标成完成，也不要求用户反复点验。

## 资源与知识页面的具体操作规划

### 模板库

先找模板，再查看结构、适用产品和参考案例，最后引用到内容安排。使用卡片和右侧详情；筛选在用/归档、产品及标签。测试结果与来源素材用稳定标识关联，不复制成另一个实验。当前读取阶段不开放归档、删除或创建使用记录。

### 标题库

以标题正文为主要信息，按批次/方向/产品筛选。详情查看同批内容、适用说明和使用记录；复制仅影响本机剪贴板时不自动记为一次发布。后续统计使用事件须由原业务接口确认，不以“打开详情”增加次数。

### 工具箱

按用途组织工具入口，卡片显示名称、说明及打开按钮。只接受 http/https 的有效工具链接，不在描述中显示账号凭据；不套旧系统复杂管理页。

### 知识库与学习复盘

共用查找/分类/标签和详情阅读布局。长期知识与学习过程分视图，内容仍保留同一条资产标识；没有可靠分类时展示原类别，不猜测作者和可见范围。测试结论继续从实验读取。来源链接在详情打开，站内权限不代表来源文档权限。

### 成员、账号与基础资料

成员显示工作分工、在职信息和关联情况；账号显示运营归属与状态。登录用户、成员档案、业务运营账号三者分开。管理员页面保留服务端限制，敏感号码默认掩码，不增加工资或绩效推断。店铺仅维护一次，产品和财务引用同一店铺标识。

## 财务、资产与管理页面的具体规划

- 记账本：按发生日期查看收支原始记录，筛选店铺/分类/垫付人，详情查看凭证与结算关联；金额使用整数分，不以浮点累计。
- 结算与报销：突出未结清垫付与实际付款记录，月份仅筛选。选择结算不等于付款，跨月不清零，部分付款沿用已确认的实际记录而不自动结清。
- 工作室财产：优先显示已有样品档案与领还事实；设备没有数据能力时明确保留，不能把样品当完整设备库。
- 仓库管理：产品库存、包材库存是独立库存事实，不能拿产品档案数量或样品数量冒充库存。先核查底层，不存在则记录为需要新增能力，不显示编造结余。
- 考勤：记录与审核两种视图，显示日期、状态、原始记录与更正历史；不推算工资或罚款。未知制度不自行计算。
- 用户与角色：查看登录账号与角色/启停状态，角色更改属于单独管理操作，不在成员编辑中混入。
- 账户资料：具体含义尚未明确时保留边界说明，不复制店铺或运营账号形成第二套资料。
- 数据驾驶舱：首轮仅汇总当前可见执行事项的发布/回填事实，说明累计范围；不把发布量当成销售或测试成功，不推断未定义的爆款阈值。

## 内容创作与待补齐能力

- 内容创作先提供手动创作工作区：选择参考素材/模板 → 编写标题、正文、封面说明 → 保存本人本机草稿、复制或导出 → 跳转关联的已有执行事项。
- 核查现有业务服务后未找到独立内容草稿 API。本轮草稿明确仅在本机、按登录用户隔离，不能称为已同步团队或已发布；不创建平行数据库来假装接通。
- 不因尚未确认 AI/批量能力而自动发送内容至外部模型。模板结构由用户点击插入，不增加后台使用次数。
- 账户资料先提供统一资料索引，链接现有店铺、运营账号与个人资料，不另建含义不明的“账户”表。
- 仓库管理显示产品档案与库存连接状态；实际库存、包材库存和出入库流水的底层缺失明确列为待补齐，不用样品库存冒充。

## 写入接入安排

- 当前云端读取入口继续禁止写入。新写入代码单独在隔离夹具中验证，连接模式由打包配置显式选择，不因添加保存按钮自动开放现有云端数据。
- 先接入已存在且契约明确的素材新增/编辑、产品资料新增/编辑、发布与观察回填。请求沿用原有 API，不新写后端和数据库。
- 写入只在登录会话具备 CSRF token 时发送；409 冲突保留编辑内容，未知网络结果不自动重发。
- 素材归档不能映射为删除；个人事项的计划日期/截止时间在旧 Todo API 中缺失，需兼容扩展后才开放完整写入，不静默丢弃日期。
- 旧服务写入能力的历史测试继续作为参考，当前环境的模拟请求验证不能冒充云端真实写入验收。
