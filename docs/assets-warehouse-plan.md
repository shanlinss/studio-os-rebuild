## 首版边界与暂定规则

这是为 4 人团队选择的最小实现建议，不扩展成采购、订单或 ERP 系统：

1. 样品维持原数量式借还；设备按“一物一档”管理。借用人、保管人都引用原成员标识，关联拍摄仍引用原需求。
2. 仓库先采用单仓、人工登记出入库。产品库存引用原产品；规格需要区分时增加库存项目的规格说明，不直接用产品档案数量当库存。
3. 包材独立建项目，先使用整数基础单位，如件/包/卷。米、半卷、换算等需求未确定前不引入小数或自动换算。第一次登记流水后锁定基础单位，避免历史数量改变含义。
4. 财产/仓库的团队管理入口沿用管理员范围；员工在拍摄相关入口查看可借设备并办理本人借还，不获得整套仓库管理权限。
5. 新增库存项目先显示“待登记期初数量”。由管理员实际盘点并提交期初记录，明确确认 0 也必须留记录，不从旧产品或样品数据猜测。
6. 设备采购额、库存成本、折旧和利润不在这轮数量管理中自动计算。采购或报销沿用记账本，库存登记不再次制造支出。

后续实现以这些暂定规则为默认基线，若与补充的业务资料冲突则修订；目前没有据此修改真实业务数据。

## 页面与操作

### 工作室设备

在工作室财产管理中增加“设备”视图，与原“样品”视图并列。列表只展示设备名称/编号、保管人、位置和实际状态。详情集中维护基本资料、本人借还、维修记录和历史，不新增独立设备操作中心。

管理员：登记设备 → 指定保管人与位置 → 查看使用状态；可记录送修/修复与停用。员工：从可借设备选择 → 填使用位置和可选拍摄需求 → 本人归还并填写完好/异常说明。已有借用的设备不能再次借出；有未归还借用时不能直接报废。归还发现异常先进入待维修，不能直接作为可借设备展示。

建议数据：

| 对象 | 最少字段与关联 |
| --- | --- |
| equipment_assets | 独立标识、唯一设备编号、名称、型号/说明、原保管成员标识、位置、状态、版本、创建者和时间 |
| equipment_loans | 设备标识、原登录及成员标识、可选原拍摄需求标识、借用/归还时间、使用位置、归还状况、版本 |
| equipment_events | 设备标识、原借还标识、借用/归还/送修/修复/停用动作、原因、操作者、前后状态和时间 |

每件设备最多一条未归还借用，由数据库唯一约束和事务锁共同保证；历史借还和维修不覆盖。停用/报废保留档案，不删除已有引用。新增表只补设备事实，不复制原样品库存。

### 产品及包材库存

仓库管理分产品与包材两种项目，复用同一组数量流水逻辑：登记项目 → 确认基础单位与期初数量 → 入库/出库 → 查询流水 → 盘点差异调整。调整必须写明原因，记录实际盘点数及差异，不直接覆盖旧流水。

建议数据：

| 对象 | 最少字段与关联 |
| --- | --- |
| warehouse_items | 项目标识、唯一编码、产品/包材类型、可选原产品标识、规格/名称、基础单位、位置、期初是否已确认、当前数量、启停和版本 |
| warehouse_movements | 项目标识、期初/入库/出库/盘点调整、带方向数量、变动前后结余、原因、操作者、发生时间、可选来源记录、请求标识 |

数量变动和流水写入同一事务；出库不得造成负库存。请求标识与内容摘要防止重试重复入库或扣库。已登记流水不能直接编辑或删除，纠错使用引用原流水的调整记录。库存查询分页，服务端提供全量汇总，不能对当前页求和后当成总库存。

产品转样品后续需要单独的原子操作：一次事务中扣产品库存、追加原样品库存并记录双方来源关系。不得通过先调用一个 HTTP 接口、再调用另一个接口拼接完成，也不能新增第二套样品表。在该能力实现前，不开放自动转样品入口。订单扣库、售后退货、多人审批、跨仓调拨及自动补货本轮暂不接入。

## 实现顺序和完成证据

1. 设备档案与状态 → 本人借还 → 维修与停用历史。
2. 仓库项目与明确期初 → 人工入库/出库 → 流水查询及盘点差异。
3. 在规则和来源明确后，再补产品转样品的事务衔接。

先落字段/约束和追加式迁移，再接原服务权限与界面。需要的自动验证包括：重复请求只记一次、并发借用/出库不能重复或超量、员工不能代别人归还或调整库存、变更版本冲突、未登记期初与真实 0 的区别、单位锁定、历史不被覆盖，以及产品转样品双边一起成功或回滚。真实页面操作核对继续按用户要求暂停；恢复后再核对完整页面流程。
