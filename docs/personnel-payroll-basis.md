# 人员适用日期与管理员免打卡工资

本轮完成待完善清单第1项的当前范围，继续使用原成员、登录账号、考勤、工资草稿和确认记录。没有重建身份或连接，也没有将旧前端替换进新设计。

## 在职日期

团队成员详情新增“在职适用日期”和“资料变更历史”。入职日与最后在职日都按北京时间自然日期，最后在职日包含当天；未登记结束日表示尚无结束日期，不能由业务停用、账号停用或自由文本在职状态推断离职日期。

管理员填写日期及必填更正原因，按原成员版本更新。日期、原始前后值、操作者和私人回执同一事务保存，重复请求回放原结果，版本冲突拒绝覆盖。复用原identity_events，新增不可改写保护及历史分页；旧事件也能查看。原资料编辑兼容保留入职日期字段，网页对已有成员改为只读，日期调整引导到新入口；旧接口变更仍保留原成员审计。

登记结束日必须同时有入职日，且结束日不早于入职日。原接口也不能把已有结束日的入职日清空或改到结束日之后。

月度考勤只在登记的在职区间计计划工作日、正常/异常及请假汇总；区间外日期明确标注，原始打卡、请假、补卡仍可追溯，不删除原事实。区间外登录依旧按原账号状态鉴权，但不自动登记上班，不补写签退；日期不等同于停用账号。月中工资仍由薪资授权人员人工确认，不增加按天扣薪或折算公式。

新结束日期改变来源时，相关锁定考勤/工资需要重新核对，历史快照不变。结束日为空时，原员工考勤来源指纹继续使用原成员投影，避免仅因追加空字段就让全部旧锁定失效。

## 管理员工资依据

工资候选包含原账号关联的管理员和员工。员工仍须有效考勤月份锁定；管理员如果当月存在原打卡、请假、补卡或考勤锁定等员工历史材料，也继续走原考勤核对，不能因后来变为管理员而绕过。

只有当前为管理员、当月无上述历史材料、月份已结束且人员日期与月份相交时，薪资授权人员可明确登记当月免打卡工资依据。必须填写说明、勾选已核对，并匹配当前人员来源与前一核对版本。它不生成打卡、不填充正常出勤天数，也不直接决定工资金额。

免打卡依据保存当月人员适用快照、说明、操作者及递增版本，历史不可改写并支持分页。普通员工不能使用此接口；普通财务授权不等于薪资授权。当前人员/资源仍沿用原管理员范围，进一步细分授权是下一项。

草稿引用有效考勤锁定或明确的管理员免打卡核对，两种依据分别保存。前者必须有原closure_id，后者closure_id为空且必须有admin_review_id；原attendance_hash字段继续保存适用依据指纹，不伪造一条考勤锁定。Excel导出记录固定格式版本：新文件采用支持免打卡依据的第2版，旧payload未标版本继续按原格式生成，固定SHA-256回归保证旧文件重新下载的字节不变。薪资确认快照和Excel依据表同步支持两种引用，管理员可完整走草稿、确认和导出。

人员日期、角色或当月历史材料变化后，原免打卡依据/草稿显示变化；重新成为员工不能保留管理员豁免。来源不一致时阻止确认和新导出，历史工资与此前导出文件继续保留。重复核对本身形成新依据版本，也需显式修订草稿引用。
