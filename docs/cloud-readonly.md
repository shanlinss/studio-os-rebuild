## 新界面的真实只读预览

启动：`npm run dev:cloud`（无依赖安装）。地址：`http://[::1]:4174/`。

- 仅监听 IPv6 loopback，固定经既有 `[::1]:13102` 通道读取原服务。
- 新 UI 与原入口使用同一主机名，所以浏览器可自然携带既有 HttpOnly 会话 Cookie；没有提取 Cookie 到聊天、文件或前端存储，也没有重新发送登录密码。
- 本地开发代理只允许列出的 GET 路由。POST/PATCH/PUT/DELETE 均在本地拒绝，不转发到云端。
- 只转发现有会话 Cookie 到该固定上游，不接受任意目标 URL、不转发其他 Cookie，不传递响应 Set-Cookie。
- `/api/session` 响应只交给前端必要身份信息，去除 CSRF mutation token。
- 验证 Host 和 API 请求来源；未知路径、额外查询参数和上游重定向拒绝，响应 no-store。
- 新预览不应用迁移、不执行数据库 SQL、不上传文件、不部署云端，也不暴露数据库端口。

这些只是本机联调入口的约束；业务权限仍由原服务验证，不能以菜单显示代替服务端授权。

## 已接入页面

| 页面 | 原有 API | 保留的语义 |
| --- | --- | --- |
| 素材收集箱及详情 | `/api/materials` 与 `/:id` | 稳定 ID、version、metadata 原字段、附件信息；空历史 metadata 可读，不擅自补写 |
| 素材实验室及详情 | `/api/lab/experiments` 与 `/:id` | 实验、轮次、关联素材、执行事项与原状态 |
| 今日工作 | `/api/workbench/profile`、`/api/tasks`、`/api/workbench/todos` | 业务任务与持续个人待办分开，管理员按成员 id 筛本人，员工沿用后端本人范围和已脱敏字段 |
| 我的执行记录 | `/api/workbench/completed?date=...&source=all` | 真实产出日期；管理员携带本人 member 过滤，不以计划日期伪造完成 |
| 测试结论 | 实验列表的 finding/recommendation | 直接引用已有结论 |
| 执行详情 | `/api/tasks/:id` | 解析 task/publications/snapshots 包装，按 publicationId 关联历史快照，null 与 0 区分 |

其他导航显示当前规划说明。没有把旧导航分组覆盖到用户指定的 PDF 规划中。
