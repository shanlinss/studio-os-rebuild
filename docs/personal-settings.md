# 个人资料与本人改密（2026-11-05）

## 范围与复用

核查旧包后，个人资料继续使用原 Members.ownProfile，按当前登录账号关联到唯一成员，不使用管理员目录投影，也不接收他人成员ID。姓名、岗位、入职/最后在职日及在职状态继续由具备personnel授权的管理员维护。登录用户名固定用于识别账号；角色、权限和成员关联仍由原账号管理流程处理。没有增加昵称、联系方式、第二套成员档案或员工自行修改任职信息。

个人页每次进入重新读取本人资料、登录角色与账号版本；尚未关联成员时明确说明，不自动匹配姓名或关联其他成员。有人员维护权限者可进入原团队成员页。旧服务未部署新接口时继续展示原资料，并说明本人改密尚不可用；只读预览不展示改密表单。

本人改密需要验证当前密码，新密码沿用原12–128字符规则，不能与当前密码相同；前端要求再次输入确认。继续使用原password模块的scrypt散列/旧散列验证、原accounts/sessions，以及原登录接口，不创建新登录体系，不触发额外考勤操作。

## 一致性与凭证保护

追加082仅扩展原account_lifecycle_events的动作约束，新增password-change。成功操作递增原账号版本、撤销包括当前设备在内的所有旧会话、追加原凭证操作审计，在同一事务提交。修改后回到登录页，原密码失效，新密码仍登录原账号/成员身份。

复用原账号操作全局事务锁与账号锁，校验当前账号有效、原散列未变、会话仍有效及账号版本，避免并发重置/撤权/停用或其他登录使旧验证继续生效。仅当前会话关联账号可操作，输入不接收目标ID、角色、成员关联等字段，原CSRF保护保留。

原login_limits承载本人改密的按账号尝试限制（15分钟20次），失败验证也计数；沿用原散列计算的并发限制。原审计只记录账号安全投影、固定操作原因、版本和请求标识；不保存明文密码、散列、密码指纹、会话或CSRF。新密码散列仅写回原accounts.password_hash。

所有提交结果均清空密码框；离开页面也清空。当前密码错误不退出有效登录；版本变化要求刷新后再填。已确认成功、旧登录失效或结果不明分别提示，结果不明不自动重试，转到登录核对。新登录后重新读取个人设置才解除该改密操作的未确认状态；没有公开的匿名改密回执入口，也不把密码存入浏览器本地存储。

## 验证与边界

自动覆盖本人/他人/未关联资料范围、输入/CSRF、原身份及考勤不变、全会话撤销、旧密码拒绝/新密码登录、角色与权限保持、失败回滚、两会话竞争、尝试次数/到期恢复、失效/外来会话、审计不可改写与不含密码、表单密码清空/版本刷新及未确认结果恢复。全部自动检查数量见README。
