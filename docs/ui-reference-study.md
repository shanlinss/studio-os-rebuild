## 两站分别借鉴什么

| 方面 | 观察与理解 | 工作台采用方向 |
| --- | --- | --- |
| 整体层级 | BoardUI以一致的控件与面板组织密集业务信息；Notion以文字层级和留白突出内容 | 用统一组件承载业务，用清楚的排版降低阅读负担 |
| 侧栏 | 浅灰表面、分组导航、图标和名称配合，当前入口有明确强调 | 侧栏中性灰，当前项使用浅红底与红色标记，保留完整导航名称 |
| 内容区 | 白色为主，浅灰分区与细边界辅助组织 | 白色主内容，边框和间距区分模块，卡片内信息对齐 |
| 字体 | 字号、字重、行高成组定义；标题、正文和说明有明显层级 | 建立少量固定文本样式，避免每个页面单独定字号；中文正文保持清晰可读 |
| 操作 | 主按钮、次按钮、轻量操作及危险操作区分；状态反馈与尺寸保持一致 | 每个操作区突出一个主要动作，次操作用边框或文字形式 |
| 表单 | 标签、必填、帮助说明、无效与焦点状态分别表达 | 标签常驻；字段附近解释错误；保存中、保存成功和读取失败分别反馈 |
| 弹窗 | 标题、内容与底部操作有稳定结构，长内容具有明确阅读范围 | 详情与编辑区分；长表单内部滚动；保存与取消保持稳定位置 |
| 装饰 | Notion以少量角色和插图增加亲和力；公开产品界面仍以内容为主 | 小角色放在空状态、完成反馈、首次引导和提醒标题附近 |

以上是结合可见页面与公开规范形成的设计判断，不是对两个网站像素参数的复制。

## 配色与尺寸的初步基准

下列为Studio OS的拟定起点，不声称是参考网站或小红书的官方设计规范；待实际页面验证后调整。

- 品牌红以#FF2442为起点，用于品牌标识、选中项和关键强调。按钮中的文字、底色需一起校验对比度，必要时使用更深红的交互色。
- 主背景白色或极浅中性灰；正文深灰近黑，说明文字中灰；边框浅灰。减少现有大面积灰绿色及偏淡的正文。
- 成功、处理中、错误保持独立语义色，并配合文字或图标；品牌红不代替全部状态表达。
- 页面标题约28–32px，模块标题16–18px，正文13–14px，辅助说明12px起；重要信息优先保证可读性。
- 基础间距采用4/8/12/16/24/32的稳定层级；模块圆角约10–12px，控件约6–8px。阴影轻量，主要靠边界与留白组织。
- 桌面常用按钮高度约36px，紧凑操作约32px；官网营销大标题、大段装饰留白不直接搬入日常工作台。

## 小机器人/小角色的使用规则

以用户截图的亲和感为参考，建立工作室自己的角色造型。主体可为柔和的圆角纸片、标签或几何体，配深色眼睛和少量表情；统一眼睛比例、轮廓粗细、光感与材质。

主角色以红色重点或红色配件形成识别，主体保持浅色；少量柔和辅助色用于区分场景。优先先做一个主角色和少量状态，而不是为每个页面另建一套卡通形象。

适用位置：暂无事项时提供下一步、保存成功时轻量反馈、首次进入模块时给简短引导、经营提醒中增加识别。角色文案应指向实际操作。列表、表格与财务数字区域以清楚阅读为主；角色面积与动效保持克制。

可区分等候、专注、完成、需要核对等表情。状态仍有明确文字，不能只靠角色表情或颜色传达。此阶段只记录视觉方向，未增加机器人功能或生成角色资产。

## 首页后续落地顺序

先统一颜色、字体与控件规范，再调整侧栏、页面标题和日期筛选；随后修整工作清单行、经营提醒卡、空状态与弹窗。小角色随适用场景加入。之后按同一规则推广到素材、测试、拍摄、知识、人员和财务页面。

研究阶段未修改页面。后续用户授权后已进入桌面首轮实施，使用其幸运发财树完整Logo（含底部字标）；实施与实测范围见desktop-ui-baseline.md。
