## 连接现状与不能直接复制的内容

1. 根 `.env` 中 `SUDA_DATABASE_URL` 为空，只能说明该包没有提供可直接使用的原平台数据库 URL。
2. 独立系统的开发连接限定在本机指定测试库；staging 使用容器网络与 `/run/secrets/database_password` 注入，实际运行秘密不在 ZIP 中。
3. 包内未发现以 `.dump`、`.db`、`.sqlite` 等后缀保存的数据库导出。这不能排除归档内还有数据，或实际库保存在原运行环境。
4. 当前代码并非“复制 ZIP 就连上旧库”。可以复用连接实现、迁移和 API，真实连接仍需沿用原部署环境的配置。不要把秘密放进前端或提交到仓库。
5. 独立服务启动会调用迁移，第一次联调不能直接拿现有业务库试启动；先核对版本并使用隔离副本验证，再接正式配置。

## 当前原型与旧后端的主要差异

- 本地原型 `tasks` 不是数据库建表方案。已有系统区分个人 Todo、业务任务、计划、发布及观察，应通过适配器呈现，避免把多类对象硬塞到一张新表。
- 新素材类型（参考笔记/图片/视频/标题/其他）与旧素材 `metadata.mediaType/category` 两组字段不完全一一对应，转换须保留原信息。
- 新原型的“待执行/进行中/待复盘/已结束”是界面流程提案；旧实验 `testing/concluded` 与轮次/执行进度分开记录，不应直接重写历史状态。
- 新归档按钮与旧素材删除不是同一个操作；现有接口复用时不能将“归档”接到永久删除。
- 新原型自由指标与旧固定发布快照、运营观察两类记录应保持语义，避免无证据地混合比较。

## 接下来的实施顺序

1. 采用独立 `studio/server` 作为优先后端来源，整理最小构建依赖和接口清单，不运行根包的平台 postinstall。
2. 对齐登录/会话与接口响应契约，在隔离测试环境做身份与只读查询联调。
3. 先让新素材页、实验页、工作台调用已有 API，再按明确差异做少量适配或追加迁移。
4. 逐个模块接入已有产品、拍摄、知识和管理能力，保留新 UI 与整体规划。
5. 当前浏览器原型数据保留在本地，不自动上传或导入为真实业务记录。

第一轮结论：已有后端具备明确复用价值，应减少新的后端重复开发。实际连接与写入验证尚未完成，不能宣称已接通或已迁移。
