# 迟到与时长不足核实（2026-11-03）

“我的考勤”新增“我的异常说明”，管理员同页新增“异常核实”。每项异常关联原考勤工作段，迟到与时长不足分别处理；同一天可以同时有两项，清单条数不是异常天数。

本轮队列只列工作室中已完整签退、起止均在原工作日内且当天唯一的工作段。按现有规则，上班晚于北京时间 10:30 标记迟到，签退减签到不足 8 小时标记时长不足；午休不另外扣除。缺签到/签退、重复工作段、跨日、未来或异常顺序先补正，不当成零时长或直接认定缺勤。历史外勤不套用该规则。工作中可以在首页看到时间提示，正式核实队列在完整签退后处理。

## 事实与说明分开

管理员可以记录“核实属实”或“特殊情况已说明”，必须填写原因。员工只读本人说明；管理员读取团队范围。特殊说明不会修改打卡、抹去异常或自动变成正常出勤，也不自动扣款、免扣款或决定工资。

核实可以追加新说明，旧说明不覆盖。已核实的项目可说明原因后重新置为待核实，原结论和操作者历史继续保留。管理员处理时，当前源考勤版本和最新核实记录都要匹配；两人同时操作只有一个成功，另一人重新读取再处理，避免丢失说明。

补卡使原时间变化后，旧核实结论不直接套用新时间。当前仍命中异常的进入待复核；当前已不命中的显示“当前无须核实”，原说明仍保留用于追溯。详情同时展示原始与当前核准时间、当前事实、核实结论及核实时的时间快照。

队列按日期、迟到/时长不足及待核实/已核实筛选，每页 50 项。列表和总数读取同一只读快照，分页覆盖全部筛选范围；核实历史单独分页。原考勤详情也有“异常核实与说明”入口，即使当前已不在异常队列中，历史仍可查看。

## 数据和事务

044 仅新增 attendance_exception_reviews 和 attendance_exception_receipts，继续引用原 attendance_periods、账号和成员，不复制人员、考勤余额或工资。核实记录保存异常类别、结论、说明、当时原考勤版本/快照、前一条核实标识、递增序号、操作者姓名快照及实际记录时间。

核实表是不可改写的追加记录，数据库拒绝 UPDATE/DELETE。递增序号用于定位最新核实，不靠请求开始时间或随机标识猜先后顺序。原 attendance_events 同步追加核实事件，原考勤的 original/adjusted 时间及版本保持不变。

保存与原补卡/签退共用同员工的事务锁，事务中重新检查当前管理员身份，锁定原工作段，重新计算是否可核实。核实记录、原操作历史和本人持久回执一起提交或回滚；审计失败不能留下半条结论。响应不确定时先核对本人回执，不自动重复提交；其他管理员和员工不能读该操作者的私有回执。

SQL 队列与服务端原时间规则保持一致，毫秒精度统一后判断，防止不足 8 小时因时间格式差异被当作已满。原始时间字段仍保留原值。没有新增工资、罚款、豁免金额或请假折算字段。

只读代理只新增异常队列、详情、核实历史 GET 和前端模块；不转发核实 POST 或私有回执。人员管理进一步分权仍待后续实现，本轮沿用现有管理员人员管理范围。
