# 产品与包材库存首版（2026-11-03）

## 操作流程

仓库管理现为真实库存目录：管理员按产品/包材、启用/停用及关键词筛选，查看每页 50 项。产品库存关联原产品；包材独立建档，不复制产品或样品。登记编码、名称、规格、整数基础单位、位置和说明后，数量为“待登记期初”，不能直接出入库。

管理员实盘后登记期初，实际为零必须明确填 0，期初只能登记一次。之后可登记入库、出库、盘点调整，必须写原因，可写来源参考。盘点填写实际结余，由系统计算差异；没有差异也保留盘点记录。纠错可引用同一项目的旧流水，旧记录保持可查，引用可跨历史分页读取。

期初后锁定类型、原产品、规格和单位。名称、编码、位置、说明及启停仍可按版本编辑并记录资料事件；停用不清空数量或历史，重新启用后可继续登记。首版支持件/个/套/包/卷/箱的整数数量，不做单位换算、半卷或金额估值。

## 数据与保护

追加 038：warehouse_items、warehouse_movements、warehouse_item_events、warehouse_receipts。继续引用原 products/accounts/members，不创建第二套身份、产品、财务或样品。未登记数量为 NULL，数据库约束其与期初标记一致。

每次数量变化锁定原项目并检查版本、启停与期初。库存、流水和回执同一事务提交；不允许负库存或超出 2147483647 的单项数量。按操作者和 requestKey 保证重放返回原结果，改变内容复用标识冲突。客户端保存响应中断时先查本人持久回执，不自动重试增减库存。

数量流水保存登记时的原编码/名称/产品/规格/单位/位置快照、变动前后结余、原因、操作者、服务器登记时间和可选原流水引用。没有修改或删除流水 API，数据库触发器也拒绝 UPDATE/DELETE。纠错追加新盘点事实，不覆盖历史；资料编辑不能直接写数量。

列表、总数和全筛选汇总使用同一只读快照；汇总按产品/包材及单位分别统计已登记数量和待登记项数，不对当前页求和，也不混加件、包、卷。所有仓库读写均限定管理员，事务中再次核查账号当前角色和状态。

## 验证与限制

累计 118 项自动检查通过：74 项前端/接口契约，44 项真实后端/临时 PostgreSQL。验证了边界、并发、重放、权限、失败回滚、存储层不可改写、旧快照、跨页汇总与来源引用。原 001–033 文件校验不变，兼容追加至 038。

按用户要求，实际页面核对仍暂停；云端未应用迁移或启用新增写入。接口未部署时只读入口显示读取失败，不退回示例库存。

自动订单扣库、退货、多仓调拨、采购金额/记账尚未接入。产品转样品已追加实现，详见 warehouse-sample-transfers.md；仅件／个一对一，扣减原库存与增加原样品在同一事务完成。收入、成本与利润也不从数量流水推算。


## 包材按归属分账（057）

在包材详情选择「核对并分配库存」。公共库存和每家启用店铺各自登记实际数量，确认是零时填 0，留空表示本次不建立该归属。有旧总量的包材，首次分配合计必须等于旧总量。若实际盘点和旧总量有差异，先通过原盘点入口记录差异，再做分账。未登记期初的包材可直接按归属填写实盘数。

包材档案、库存总量、历史流水和请求回执沿用原结构。分账时在同一事务内建立归属余额和相应期初流水。旧流水的归属为空，保留为分账前总账记录。分账期初是余额拆分或建账，汇总时使用当前余额或项目总量，不能叠加旧总账与分账期初。分账后，管理员按具体归属登记入库、出库和盘点，库存在同一事务内更新该归属余额和项目合计。追加归属从 0 开始。停用店铺余额可查，暂停数量操作。

员工按原授权查询和操作已分账归属，详见 inventory-access.md。补货提醒按各归属当前余额生成。

## 包材采购分配（058）

在已分账包材详情选择「采购入库」。同一张采购单对应一种包材，可填写公共库存和多家店铺的数量。采购日期、供应商、单价、分配和核对依据一并保存，采购总额按分配合计乘以单价计算。金额使用精确分。需要分配到新归属时，先在包材详情建立该归属。

采购单、分配行、原库存入库流水、各余额、总量和回执在同一事务提交。普通库存流水仅展示数量变动及采购入库类型说明。采购价格、供应商、依据和财务来源仅对同时拥有财务与资源授权的管理员开放。

可引用一笔已有支出，原支出只在包材采购中引用一次。原支出金额保留为来源快照，可与采购总额不同。支出后续修改会在采购记录中提示。此操作不创建财务支出或修改原账本。

## 包材批量消耗（059）

仓库管理和员工包材页提供「批量消耗」。一张领用单可填写 1 至 100 个不同库存来源，每项选择包材、公共或店铺库存及整数数量。公共库存必须选择实际领用店铺。店铺库存沿用所属店铺。一个库存来源在一张单据中只填写一次。

管理员可登记所有启用范围。员工只能扣减具有出入库授权的范围。领用店铺用于记录实际用途，公共库存按领用店铺登记后仍只扣公共余额。保存时核对整张单据的权限、余额和版本。单据、原出库流水、归属余额、项目总量及回执一起提交。同一请求重复提交返回原回执。流水可回到批量领用单；员工只能查看自己登记、且各行仍在授权范围内的领用单。

## 包材调拨（060）

在包材详情选择「包材调拨」，资源管理员可在同一种包材的两个启用归属之间移动整数数量。公共库存与店铺可双向调拨，两个店铺之间也可调拨。目标归属须先建立。员工继续按库存范围登记出入库，调拨由资源管理员维护。

一次保存同时核对双方余额版本、调出量与店铺状态，并写入原库存出入库流水、双方余额和调拨单。项目合计不变。任一写入失败时全部回滚，重复提交返回原回执。从任一侧流水可打开调拨单，查看登记时的原归属与前后数量。

## 包材补货预警（061）

资源管理员可在包材详情为公共库存及各店铺分别设置整数阈值。当前余额达到或低于阈值即提醒。填 0 表示仅在余额为 0 时提醒，留空表示关闭。原有归属默认关闭。设置保留原因和前后值，记在原资料变更中。

仓库「只看需补货」显示至少一个归属触线的包材。管理员首页提醒逐个列出触线归属，点击可打开原包材详情或进入仓库筛选。提醒直接读取当前余额，补货到阈值以上、关闭阈值或停用包材/店铺后自动消失。

## 正式商品库存归属

已绑定启用正式商品 SKU 的原库存，可以核对公共与店铺归属。首次分配合计与原已确认总量一致，未登记期初时按实盘登记。没有店铺推断或自动分配。后续新增归属从零开始。原 product、SKU、库存项目、余额及数量流水继续使用。

商品和包材复用已有归属余额表及核对逻辑。该表保留历史名称 packaging_balances，通过原库存 kind 区分业务。包材领用、采购及预警继续只选择包材。商品可在归属间调拨，数量合计不变。分账后的入库、出库及盘点须选择具体归属，旧总账记录保留。

商品转为拍摄样品也须选择具体转出归属，在同一事务扣该归属及商品总量、增加原样品余额并保存双方流水。旧未分账库存保持原转样品入口和回执含义。员工商品数量入口随批量入库和发货继续接入。
