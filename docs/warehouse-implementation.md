# 产品与包材库存首版（2026-11-03）

## 操作流程

仓库管理现为真实库存目录：管理员按产品/包材、启用/停用及关键词筛选，查看每页 50 项。产品库存关联原产品；包材独立建档，不复制产品或样品。登记编码、名称、规格、整数基础单位、位置和说明后，数量为“待登记期初”，不能直接出入库。

管理员实盘后登记期初，实际为零必须明确填 0，期初只能登记一次。之后可登记入库、出库、盘点调整，必须写原因，可写来源参考。盘点填写实际结余，由系统计算差异；没有差异也保留盘点记录。纠错可引用同一项目的旧流水，旧记录保持可查，引用可跨历史分页读取。

期初后锁定类型、原产品、规格和单位。名称、编码、位置、说明及启停仍可按版本编辑并记录资料事件；停用不清空数量或历史，重新启用后可继续登记。首版支持件/个/套/包/卷/箱的整数数量，不做单位换算、半卷或金额估值。

## 数据与保护

追加 038：warehouse_items、warehouse_movements、warehouse_item_events、warehouse_receipts。继续引用原 products/accounts/members，不创建第二套身份、产品、财务或样品。未登记数量为 NULL，数据库约束其与期初标记一致。

每次数量变化锁定原项目并检查版本、启停与期初。库存、流水和回执同一事务提交；不允许负库存或超出 2147483647 的单项数量。按操作者和 requestKey 保证重放返回原结果，改变内容复用标识冲突。客户端保存响应中断时先查本人持久回执，不自动重试增减库存。

数量流水保存登记时的原编码/名称/产品/规格/单位/位置快照、变动前后结余、原因、操作者、服务器登记时间和可选原流水引用。没有修改或删除流水 API，数据库触发器也拒绝 UPDATE/DELETE。纠错追加新盘点事实，不覆盖历史；资料编辑不能直接写数量。

列表、总数和全筛选汇总使用同一只读快照；汇总按产品/包材及单位分别统计已登记数量和待登记项数，不对当前页求和，也不混加件、包、卷。所有仓库读写均限定管理员，事务中再次核查账号当前角色和状态。

## 验证与限制

累计 118 项自动检查通过：74 项前端/接口契约，44 项真实后端/临时 PostgreSQL。验证了边界、并发、重放、权限、失败回滚、存储层不可改写、旧快照、跨页汇总与来源引用。原 001–033 文件校验不变，兼容追加至 038。

按用户要求，实际页面核对仍暂停；云端未应用迁移或启用新增写入。接口未部署时只读入口显示读取失败，不退回示例库存。

自动订单扣库、退货、多仓调拨、采购金额/记账尚未接入。产品转样品已追加实现，详见 warehouse-sample-transfers.md；仅件／个一对一，扣减原库存与增加原样品在同一事务完成。收入、成本与利润也不从数量流水推算。
