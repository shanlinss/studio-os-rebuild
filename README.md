# Studio OS · 重新开发

为 4 人小红书电商运营团队开发的内部 Web 工作台。整体规划依据用户确认的网站地图，保留七中心、29 个页面入口；页面有入口不代表该页全部业务已上线。仅开发桌面网页，沿用已确认的新设计，UI 细节后续统一调整。

## 当前实现与验证

复用旧包的原数据库、身份、业务服务和关联标识，前端以本项目为主。已接入本机真实保存与自动验证的范围包括：个人事项；素材与私有附件；实验、后续轮次、派发、发布回填与复盘；拍摄与样品；成员/运营账号/店铺；财务支出/凭证/结算/报销；登录关联、账号开通/密码重置及已有账号权限；设备档案与借还/维修；产品及包材库存。

库存首版支持项目登记、明确期初（含 0）、入库、出库、盘点纠错、不可改写的流水、分页及按单位的全筛选汇总。产品引用原档案，样品仍独立沿用原库存；产品转样品支持件／个按一对一登记，在同一事务扣商品、加原样品，并保留双边记录；没有自动订单扣库或采购记账。

当前 247 项前端/接口契约与 373 项真实后端检查通过，共 620 项。原 001–033 迁移校验保持，兼容升级追加至 080。按用户要求，新增范围的实际页面操作核对继续暂停；云端仍只读，没有应用新迁移或部署新保存接口。

## 三种本地入口

- **云端只读**：保持原 SSH 通道和登录，运行 `npm run dev:cloud`，打开 `http://[::1]:4174/`。只转发白名单 GET；新接口尚未部署时显示读取失败，不用示例数量填充。参见 [云端只读接入](docs/cloud-readonly.md)。
- **本机原后端预览**：`npm ci` 后运行 `npm run dev:integrated`，打开 `http://127.0.0.1:4178/`。启动全新临时 PostgreSQL 和公开测试身份，退出后清理，不连接云端；不可作为正式数据存储。参见 [后端复用与兼容](docs/backend-compatibility.md)。
- **早期静态示例**：运行 `python3 -m http.server 4173 --bind 127.0.0.1 --directory dist`，打开 `http://127.0.0.1:4173/`。此入口仍是浏览器本地示例，不能代替上面真实后端验证。

`npm test` 运行前端与接口契约检查。`npm run test:backend` 构建服务并验证原后端、迁移和权限；运行前先停止本机原后端预览，避免占用测试数据库端口 55432。测试拒绝连接已占用的数据库，不读取云端环境文件。
